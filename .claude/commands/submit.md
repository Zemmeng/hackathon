# `/submit`

> 截止前约 1 小时。以 `docs/1-brief.md` 的官方要求为准，逐项核对 `docs/4-demo.md` 的提交清单，**每项附证据**。转 public、打 tag、提交表单都由人来点。

## 第零步

重读 `docs/1-brief.md` 的提交物和规则限制（没核实的按最严）+ `hackathon.conf`。

## 第一步：仓库安全

```bash
bash scripts/check.sh                       # 全量绿
bash scripts/secret-scan.sh --history       # 零命中
```

命中 → **停下**，告诉人先轮换 key，再讨论历史清理；只报提交号和文件，不打印值。
再确认：`.env`、数据、大文件不在历史里 · LICENSE 队名已改 · 没用的 `starters/` 已删或已说明 · README 顶部评委段（截图、在线地址、视频、运行方法、英文段）已加 · 赛前模板已披露。

## 第二步：演示

`DEMO_URL` 在无痕窗口返回 200 且主路径可点 · 视频链接可播放、时长合规。

## 第三步：材料

Slides PDF 已导出 · 表单各字段草稿写进 `4-demo`「对外文案审阅」并已过目 · 成员、赛道、AI 使用披露齐全。

## 第四步：需要人点的动作，一次问一个

1. 仓库转 public（如果要求）—— **人来操作**
2. `git tag -a submission -m "提交版本 <时间>" && git push origin submission`
3. 在比赛平台提交表单 —— **人亲手提交**

## 第五步：提交后

成功页截图放 `docs/pitch-assets/` · `3-tasks` 顶部标「已提交 <时间>」· 🔒 提交后 main 不再改代码。

## 收尾

输出清单表「项 | 状态 | 证据」；没通过的项写最快修法和负责人。

## 🔒 不做的事

不替人提交表单 · 不替人改仓库可见性 · 不改代码 · 不打印任何秘密的值
