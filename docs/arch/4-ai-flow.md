# 中间怎么接 AI（流程图文字版）

图：`4-ai-flow.pdf` / `4-ai-flow.png`（内容和本文件一样）· 决定：`D-0929-1430`（大模型只读懂，引擎来选）· 接口：`docs/contract.md` §路人读数 · T5 任务说明：`T5-PRD.md`

**原则：大模型出主意，引擎算数字。** 大模型只「读懂」屏上的字；各条路走多少人、分钟数、排队长度全部由引擎算。引擎对外只露 `evaluate(方案)`：同样输入同样结果，可以反复跑。前端不在这张图里，只看两头的输入和输出。

| 步 | 做什么 | 谁 |
|---|---|---|
| 输入 | 前端交过来的施工方案：封哪段、什么时间、摆了哪些设备、屏上写什么 | 前端 T2 |
| ① | 找出受影响的车，和能绕的路（平时各要多久） | 引擎 T4 |
| ② | 写出 4 类路人各自看到了什么：按先后顺序的标志牌、屏上的字、车速下能读几秒 | 引擎 T4 |
| ③ | **问大模型：读懂屏上的字**——看到没、看懂没、叫你走哪条 / 别走哪条、说省或堵几分钟、信不信、一句理由 | **AI · T5 @jinmingq** |
| ④ | 选择模型：读数 + 每类人的参数 → 每类人走各条路的比例；两点校准校这里 | 引擎 T4 |
| ⑤ | 分车流，算延误和排队 | 引擎 T4 |
| ⑥ | 叠加附近同时段的其他施工：A、B 分别算，再一起算，多出来的就是冲突成本 | 引擎 T4 |
| ⑦ | **规划顾问（加分项）**：提 3 个改法（改屏上的字 · 挪设备 · 错开日期） | **AI** |
| 输出 | 交给前端：哪里堵、堵多久、每类人受多大影响、改法前后对比 | 引擎 T4 |

回头再算：

- ⑤ 排队变长 → 回到 ④，引擎自己重算，**不再问大模型**
- ⑦ 的每个改法 → 回到 ⑤ 用引擎重算一遍

③ 怎么问（T5）：

- 只看「字 + 人」，和路况无关，所以一句话每类人只问一次（问 3 次给区间），缓存一直有效
- 只回读数，**不回比例**
- 先查缓存；大模型挂了用关键词规则兜底
- key 只放在 Cloudflare

④ 每类人的参数（T4）：赶不赶时间 · 熟不熟路 · 信不信屏 · 怕不怕堵 · 能不能走货车路。比例不让大模型直接给：只写人设、行为差别很小，而且比真人更怕风险（依据见 D-0929-1430）。

待定：用哪家大模型、谁的 key；T4 谁做。
