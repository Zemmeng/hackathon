# 中间怎么接 AI（流程图文字版）

图：`4-ai-flow.pdf` / `4-ai-flow.png`（内容和本文件一样）· 决定：`D-0929-1333` · 细节参考（T5 开工时再看）：`5-llm-api-detail.pdf`

**原则：大模型出主意，引擎算数字。** 大模型只回答「每类路人走哪条路的比例 + 一句理由」；分钟数、排队长度全部由引擎算。前端不在这张图里，只看两头的输入和输出。

| 步 | 做什么 | 谁算 |
|---|---|---|
| 输入 | 前端交过来的施工方案：封哪段、什么时间、摆了哪些设备、屏上写什么 | 前端 T2 |
| ① | 找出受影响的车，和能绕的路（平时各要多久） | 引擎 |
| ② | 写出 4 类路人各自看到了什么：按先后顺序的标志牌、屏上的字、车速下能读几秒 | 引擎 |
| ③ | **问大模型：每类人会怎么走？**（通勤司机 · 本地人 · 游客 · 送货司机） | **AI** |
| ④ | 校准：用实地研究的数字定刻度，不直接用大模型的比例 | 引擎 |
| ⑤ | 分车流，算延误和排队 | 引擎 |
| ⑥ | 叠加附近同时段的其他施工：A、B 分别算，再一起算，多出来的就是冲突成本 | 引擎 |
| ⑦ | **规划顾问（加分项）**：提 3 个改法（改屏上的字 · 挪设备 · 错开日期） | **AI** |
| 输出 | 交给前端：哪里堵、堵多久、每类人受多大影响、改法前后对比 | 引擎 |

回头再算：

- ⑤ 排队变长 → 带上「前面排多长」回到 ③ 再问一次（最多 2 轮）
- ⑦ 的每个改法 → 回到 ⑤ 用引擎重算一遍

③ 怎么问：

- 先查缓存，演示用的问答提前问好
- 没问过才问：每类人问 3 次取平均
- 只回：走每条路的比例 + 一句理由
- 大模型挂了：用关键词规则兜底
- key 只放在 Cloudflare

为什么要校准：大模型和问卷一样是「表态」，会高估。伦敦实测里，真绕路的只有问卷说的 1/5（Chatterjee 2002）。

待定：用哪家大模型、谁的 key；①②④⑤⑥ 和 ③⑦ 分别由谁做。
