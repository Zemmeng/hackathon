## 一句话 pitch

**别人模拟的是「路少了一段」，我们模拟的是「人看到了什么、会怎么做」，以及「多个施工加在一起会怎样」。**

（思路来自队友 Mina。）展开说：施工开始前，先在网页上模拟一遍——封了这段路，大家会怎么走、会堵多久、谁受影响最大。

## 用户与痛点

**谁**：做封路方案的市政交通人员、施工方（向 RPM Hire 租护栏、标志牌、电子信息屏 VMS 的人）。

**什么场景**：施工开始前，要定封哪段路、摆哪些设备、屏上写什么。

**现在怎么痛**：

- 「多少人会绕路」靠拍脑袋，常用一个固定比例（比如 10%）。屏上写什么对排队有没有用，说不清
- 每个施工单独审都没问题；同一片、同一时间叠在一起才堵，没人算
- 只看车。电车公交乘客、行人、骑车的人、坐轮椅的人受多大影响，看不到

**我们能回答的新问题**：屏上换一句话，排队能少多少？

## Demo 的 3 个「哇」时刻（范围从这里倒推）

1. **改一句 VMS 文案，排队变短**：设备和位置都不动，只把屏上的字从「Roadworks ahead」改成「Use Russell St, save 8 min」，排队长度和各类人受的影响马上重算（数字以仿真结果为准）
2. **两个施工叠加：100 + 80 ≠ 400 分钟**：再加附近另一个施工。两个单独看都没问题，放在一起多出来的延误就是「冲突成本」
3. **账本给出错开方案**：错开几天，冲突化解；对比总延误和各人群受的影响，再放大到施工点路口看自行车和行人

## 架构

用户走的 6 步，以及每一步接哪个外部服务：

```
我们做的 6 步（都在打开网页的浏览器里）     谁做         接哪个外部服务

[1] 打开网页                                T2 web    ◀── Cloudflare：网页 + 数据文件，24 小时在线
 │
[2] 在地图上画施工方案                      T2 web    ◀── OpenStreetMap 底图（免费，页面注明来源）
 │   选路段、时间；摆护栏 / 标志牌 / VMS，
 │   写上屏上的那句话
 │
[3] 问 4 类路人：看到这些，你会怎么走？     T4 → T5   ◀── 大模型（只经 Cloudflare 调，先查缓存，默认 MOCK）
 │   通勤司机 / 本地人 / 游客 / 送货司机
 │
[4] 算影响：车往哪绕、哪里堵、多堵几分钟    T4        ◀── 提前下载的开放数据（T3 做成 JSON，不用 key）
 │   电车公交乘客、行人、骑车、轮椅各受多大影响
 │
[5] 查附近同一时间的其他施工，算叠加        T4        ◀── Cloudflare 存储：施工清单，大家看同一份
 │   100 + 80 ≠ 400 分钟
 │
[6] 给建议，前后对比                        T2 + T4       不接外部服务，只用我们自己的计算
     换一句屏上的话 / 挪设备 / 错开几天
     └─▶ 放大到施工点路口（车、自行车、     sim
         电车、行人怎么并道和过街）
```

东西放在哪：

| 放在哪 | 放什么 | 谁做 |
|---|---|---|
| 提前做好，随网页发布 | 路网 + 基础车流 JSON；演示文案的问答缓存 | T3、T5 |
| Cloudflare（lead 的账号） | 网页托管；接口 `/api/persona`、`/api/worksites`（草案）；问答缓存和施工清单；**大模型 key 只放这里** | T5、T6 |
| 打开网址的手机或电脑 | 面板、路网引擎（绕行、延误、冲突成本）、路口放大 | T2、T4、sim |

**原则：大模型出主意，引擎算数字。** 大模型只「读懂」屏上的字：注意到没、看懂没、叫你走哪条 / 别走哪条、说省或堵几分钟、信不信、一句理由；每类人每句话问一次（3 次采样给区间），不是每辆车问一次。各条路走多少人由引擎的选择模型按每类人明写的参数算，两点校准校这些参数（D-0929-1435）。所有分钟数、排队长度都由引擎算，评委问「这个数怎么来的」，每一步都说得清。

数据流 3 行：

1. 面板（T2）把施工方案交给引擎（T4）。引擎找出能绕的路，给 4 类路人各写一份「路上按顺序看到了什么」，交给 T5 的接口
2. T5 先查缓存，没有才问大模型（默认 MOCK），回每类人的「读数」（看到没、看懂没、叫你走哪条、信不信），不回比例。引擎按读数 + 每类人的参数算各条路的比例、分车流、算延误；堵了会改主意：排队变长时引擎自己重算，不再问大模型（D-0929-1435），结果回面板
3. 施工清单存在 Cloudflare。引擎分别算 A、B，再一起算 A+B，多出来的就是冲突成本：`D(A+B) − D(A) − D(B)`，D 是总延误（分钟）

选栈理由：见 decisions `D-03`（零构建网页 + Cloudflare）和 `D-0929-1215`（选题和方向）。计算放在浏览器里，改一句话马上出结果，也不用我们一直开着服务器。付费调用默认 MOCK，见 `D-09`。

## Mock 与假数据

- `MOCK=1` 时各模块返回什么：
  - **api（T5）**：不调大模型，按关键词规则返回。屏上有「Use X」「save N min」就提高绕行概率。演示用的文案提前真问一遍、存进缓存，演示时基本不现问
  - **engine（T4）**：真路网没到之前，先用 5×5 小方格；T5 接口没通之前，路人选择用同一套关键词规则
  - **roads（T3）**：不用 mock。产物就是静态 JSON，不调接口、不用 key
  - 真去问大模型之前，先报次数和大概花费（`D-09`）；花了就记进额度台账
- 机器人 / 假用户怎么起（人没凑齐也能测完整流程）：不需要机器人，没有多人同时在线的环节。「路人」本身就是 4 类 agent：通勤司机 50%、本地人 25%、游客 10%、送货司机 15%（占比先按假设写，T5 找数据校准）。一个人打开网页 + MOCK，就能走完三幕
